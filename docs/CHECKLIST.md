# CHECKLIST.md：验收清单

## 1. 使用方式

每个开发切片结束时，都要按本文档检查。

检查结果必须在任务汇报中说明：

- 已通过哪些检查。
- 哪些检查未执行。
- 未执行的原因。
- 是否存在需要人工批准的风险。

## 2. 通用任务检查

### 2.1 范围检查

- [ ] 本次任务目标清晰。
- [ ] 修改范围与任务目标匹配。
- [ ] 没有顺手实现无关功能。
- [ ] 没有提前实现后续里程碑功能。
- [ ] 没有改变已确认的产品策略。

### 2.2 文档检查

- [ ] 已阅读 `SDD-独立开发者代运营Agent.md`。
- [ ] 已阅读 `AGENTS.md`。
- [ ] 已阅读 `SPEC.md`。
- [ ] 已阅读 `ARCHITECTURE.md`。
- [ ] 已阅读 `DEV_PLAN.md`。
- [ ] 若行为或架构变化，已同步更新相关文档。

### 2.3 安全检查

- [ ] 没有提交 `.env` 或真实密钥。
- [ ] 没有在代码中硬编码 API Key、Cookie、密码。
- [ ] 日志不会输出明文凭证。
- [ ] 外部 API 调用不会泄露未授权客户信息。
- [ ] 内容发布或导出前保留人工审核步骤。

### 2.4 数据检查

- [ ] 数据模型与 schema 一致。
- [ ] 后端 schema 与前端类型一致。
- [ ] 状态字段使用明确枚举。
- [ ] 写操作有明确失败行为。
- [ ] 数据迁移策略已说明。
- [ ] 删除操作有确认或清晰约束。

### 2.5 API 检查

- [ ] API 路径符合 `/api/v1` 约定。
- [ ] 请求体结构明确。
- [ ] 响应体结构明确。
- [ ] 错误响应使用统一格式。
- [ ] 列表接口支持必要分页或筛选。
- [ ] Swagger 或等价接口文档可见。

### 2.6 前端检查

- [ ] 页面服务真实工作流，不是静态摆设。
- [ ] 表单有校验。
- [ ] 加载状态可见。
- [ ] 空状态可见。
- [ ] 错误状态可见。
- [ ] 保存成功或操作成功有反馈。
- [ ] 文案不溢出容器。
- [ ] 列表和状态标签便于扫描。

### 2.7 测试检查

- [ ] 新增逻辑有对应测试或说明为什么暂不测试。
- [ ] 测试覆盖成功路径。
- [ ] 测试覆盖关键失败路径。
- [ ] 状态流转有测试。
- [ ] 外部服务调用使用 mock 或 dry-run。

## 3. M0 文档验收

- [ ] `SPEC.md` 明确 M1 MVP 闭环范围。
- [ ] `ARCHITECTURE.md` 明确技术栈和分层边界。
- [ ] `DEV_PLAN.md` 明确 M1 是 MVP，M2/M3 是内容优化。

## 4. M1 MVP 闭环验收

M1 完成时，必须能走通：

```text
客户建档
→ 产品画像生成/编辑
→ 运营策略方向生成/编辑
→ 一周内容排期生成/编辑
→ 文字内容生成/编辑
→ 人工审核
→ 复制或导出内容
```

- [ ] `backend/` 目录存在。

- [ ] Alembic 初始化完成。

- [ ] Next.js 应用可启动。

- [ ] README 写明启动步骤。
- [ ] `.gitignore` 包含 `.env`、虚拟环境、node_modules、构建产物和数据库文件。

### 4.2 客户建档

- [ ] `clients` 表存在。
- [ ] 创建客户 API 可用。
- [ ] 客户列表 API 可用。
- [ ] 客户详情 API 可用。
- [ ] 更新客户 API 可用。
- [ ] 更新客户状态 API 可用。
- [ ] 删除客户 API 可用。
- [ ] 支持搜索。
- [ ] 支持状态筛选。
- [ ] 支持分页。
- [ ] 客户列表页可访问。
- [ ] 客户创建表单可提交。
- [ ] 客户编辑表单可提交。
- [ ] 客户详情入口可用。

- [ ] 可以查看版本历史。

### 4.4 运营策略方向

### 4.5 一周内容排期

- [ ] `plans` 表存在。
- [ ] `schedule_items` 表存在。
- [ ] 可以生成未来 7 天内容排期。
- [ ] 排期项包含日期、时间、平台、主题、内容形式、角度提示、状态。
- [ ] 可以编辑排期项。
- [ ] 可以删除排期项。
- [ ] 可以标记跳过。

### 4.6 文字内容生成

- [ ] `content_items` 表存在。

- [ ] 可以为排期项生成文字内容。
- [ ] 内容生成后进入 `pending_review`。
- [ ] 生成内容包含标题、正文、标签。
- [ ] 可以编辑内容。
- [ ] 可以重新生成内容。
- [ ] 重新生成保留版本历史。

- [ ] 没有外部 API Key 时 mock provider 可用。

### 4.7 审核与复制导出

- [ ] 审核队列展示正确。
- [ ] 可以按客户筛选。
- [ ] 可以按平台筛选。
- [ ] 可以审核通过。
- [ ] 可以编辑后通过。
- [ ] 可以拒绝并记录原因。
- [ ] 可以延后。
- [ ] 非 `pending_review` 内容不能被错误审核。
- [ ] 审核通过内容可以一键复制。
- [ ] 审核通过内容可以导出 Markdown 或 JSON。

- [ ] 不接入真实平台发布。

## 10. 发布前人工批准门禁

以下事项必须人工批准：

- 新增或修改数据模型。
- 新增或修改 API 契约。
- 接入真实 LLM provider。
- 接入真实图像或视频 provider。
- 存储平台凭证。
- 接入真实平台发布。
- 从 dry-run 切换到真实发布。
- 删除客户或级联删除数据策略。
- 任何可能上传客户数据到第三方的行为。
